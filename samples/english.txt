Spid3r — slide-by-slide narration script (for text-to-voice)
SOURCE: presentation_spid3r_english.html · 22 slides · each "[[SLIDE n]]" block matches one slide.

[[SLIDE 1]]
Meet Spid3r, version 1.5.0 — one front end, four backends, and zero runtime dependencies. Powered by Rust Stage 0 and the self-hosted spid3r-self compiler with LLVM 23.1 AOT, built by ANSNEW TECH with AI assistance.

[[SLIDE 2]]
What is Spid3r? You get focused CLIs — spid3r, sp, yamc, yamcvm, spvm, and spkg — with four parity backends and automatic YamGC memory cleanup. The core stays compact: 6 data types, 40 keywords, over 20 containers, and 26 stdlib modules.

[[SLIDE 3]]
Getting started takes one install from the Microsoft Store, setup installer, install script, or Cargo, with an offline VS Code extension included. Write code in dot matrix or dot mt files, and use sandbox mode to isolate untrusted scripts.

[[SLIDE 4]]
Every source file passes through one front end — lexer, parser, semantic checker, and lowering — into four identical backends: Tree Oracle, the 60-opcode spvm VM, LLVM 23 AOT with spid3r-self, and WebAssembly, all backed by YamGC.

[[SLIDE 5]]
Spid3r is tested continuously against a 136-file frozen corpus and protocol fuzzing. Write your code once and ship it five ways: spvm bytecode, yamc native apps, browser WebAssembly, desktop GUI windows, or embedded in Rust via spid3r_lang.

[[SLIDE 6]]
Imports search six locations in order, starting with your current folder and ending with the 26 embedded stdlib modules. Path escapes like dot-dot are blocked across every engine, and vendor packages are verified with SHA-256 and Ed25519.

[[SLIDE 7]]
The built-in spkg package manager connects to spid3r-spkg.github.io, Git, or local folders. It tracks dependencies in spider.toml, locks hashes in spider.lock, stores files in vendor, and never runs hidden install scripts.

[[SLIDE 8]]
Spid3r separates code into four trust tiers: T0 is the immutable stdlib, T1 is your project code, T2 is verified vendor packages, and T5 is native C FFI — which runs with full OS access in AOT builds only.

[[SLIDE 9]]
Compile any script into a standalone executable with yamc and LLVM 23, linked against the pinned spid3r_lang runtime. Add a custom icon, hide the console window, or embed UI assets with simple flags.

[[SLIDE 10]]
You can compile SHA-256 verified dot matrixc bytecode with yamcvm and bundle it with your UI assets and runtime into one executable. Remember that bytecode hides source text, not secrets — never store passwords in client apps.

[[SLIDE 11]]
Spid3r keeps the language core clean with six data types — int, float, bool, string, null, and bytes — plus safe casting with as, and only forty reserved keywords grouped by role.

[[SLIDE 12]]
Null safety prevents sudden crashes using question-mark-dot safe chaining, double-question-mark fallbacks, and automatic narrowing. Strings support clean variable interpolation, decimal formatting, and negative indexing.

[[SLIDE 13]]
If-expressions return values directly, loops handle maps and lists cleanly, and closures remember state. Chained filter, map, and reduce keep data pipelines readable, while default lists and maps never leak across calls.

[[SLIDE 14]]
Pattern matching with match verifies every enum case before execution. For runtime errors, try, catch, and finally recover cleanly — guaranteeing your cleanup code always runs.

[[SLIDE 15]]
Organize larger apps with classes, single inheritance, and shared interfaces. Fields stay private by default, while extends, super, and explicit self keep object behavior clear.

[[SLIDE 16]]
Write generic functions once with constraints like Numeric: LLVM 23 specializes and unboxes them for native speed. Over twenty built-in containers — from lists and maps to tries, heaps, and graphs — include lock-free sorting.

[[SLIDE 17]]
Need fast linear algebra? Built-in vectors and matrices support over sixteen million floats with zero extra installs — handling matrix math, linear solving, and direct Python NumPy file compatibility.

[[SLIDE 18]]
With no global lock, Spid3r runs up to 256 workers across real CPU cores using an M-to-N scheduler. Pass messages safely with channels, or use async, mutexes, atomic integers, and built-in deadlock detection.

[[SLIDE 19]]
Spid3r includes 26 embedded stdlib modules and 254 native builtins — covering SQLite, PostgreSQL, MySQL, web servers, WebSockets, 598 time zones, JSON, CBOR, big numbers, and testing tools.

[[SLIDE 20]]
We are transparent about security: built-in hashing, Ed25519, and OS native-tls pass standard tests, though an independent third-party audit is pending. Keep critical production secrets behind a trusted gateway or hardware vault.

[[SLIDE 21]]
One spid3r.ini file manages 45 settings across 12 sections with live reload. Monitor status, safety switches, and logs locally using spid3r control or the desktop control panel — nothing leaves your PC.

[[SLIDE 22]]
One language, everything built in: Spid3r v1.5.0 with spid3r-self, LLVM 23.1, YamGC, 254 builtins, 26 modules, and zero external dependencies. Thank you from ANSNEW TECH and the Spid3r Language Project.
