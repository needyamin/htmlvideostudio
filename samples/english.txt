[[SLIDE 1]]
Meet Spid3r. A modern, high-performance, memory-safe, embeddable, general-purpose programming language. Built from scratch in Rust, with zero external dependencies. Version v1.1.1, Language 1.0. WebAssembly ready. From ANSNEW TECH, and the Spid3r Language Project, 2026.

[[SLIDE 2]]
What is Spid3r? One language, four design tenets. First, zero external dependencies: compiler, virtual machine, AST interpreter and standard library — regex, crypto, calendars, compression — all pure Rust. Second, dual execution engines: engine vm or engine tree, with one hundred percent byte-for-byte behavioral parity. Third, a zero-leak tracing garbage collector: a deterministic mark-and-sweep cycle collector, with the first pass after one thousand and twenty-four tracked allocations. Fourth, a native WebAssembly core: a self-contained linear-memory engine in browsers, Node.js, Deno and Edge Workers. By the numbers: six primitive types, forty reserved keywords, twenty-plus data structures, and twenty-six standard library modules.

[[SLIDE 3]]
One binary, a full development environment. Three ways in: on Linux and macOS, the install script; on Windows, a setup executable; or Cargo install. The version command prints spid3r 1.1.1, language 1.0, Rust host, no runtime dependencies. The REPL keeps a five-hundred-entry history. No runtime to install — only GUI mode borrows the system webview, and programs live in dot matrix files. Here is Hello World: fn main, println Hello World, a language variable set to Spid3r, the year 2026, a welcome line with the version, and return zero. The browser playground runs top-level code and synthesizes an empty main; the CLI needs fn main with return zero. Run with --sandbox denies filesystem, network, process and environment access, and denied calls raise a catchable, sandboxed, access-denied error.

[[SLIDE 4]]
The compiler and VM pipeline. Six phases: one, the lexer produces a token stream; two, the parser builds the AST; three, semantic analysis validates it; four, lowering reduces it to core primitives; five, the backends produce stdout; six, the garbage collector reclaims cells. The checker recovers up to twenty-five syntax errors per pass, with a strict nesting depth of sixty-four. The bytecode machine has sixty opcodes with pre-decoded superinstructions. Native ahead-of-time compilation uses LLVM 23 with 2D row unboxing, split staticlib linking, and a compact sixteen-byte Value layout. One front end, four backends, and the WebAssembly build is the same VM. Stdout, error phase and exit code must match exactly. A corrupt bytecode container is rejected before the first instruction runs. A parity bug is fixed and pinned: early 1.0 builds miscompiled not of A or B on the VM when A was falsy — caught and closed by the engine parity tests.

[[SLIDE 5]]
CI, releases, and one source with five outputs. The CI workflow runs six jobs: core, GUI and WASM builds, native ahead-of-time compilation, and automated engine-parity testing on every change. The release workflow produces four platform tarballs and a Windows installer. The fuzz workflow runs scheduled fuzzing regression tests on the compiler front end. One source, five outputs: a dot matrix source with one front end; spid3r run for direct execution; spid3r build for an ahead-of-time native executable; bundle target wasm for a browser module; spid3r gui for a desktop webview app; and the spid3r_lang crate to embed in a Rust host.

[[SLIDE 6]]
Where code comes from. Six roots, resolved through one shared implementation. One, the importing file's own directory. Two, SPID3R_PATH, a semicolon-separated list. Three, dot slash stdlib, relative to the working directory. Four, a stdlib folder beside or above the executable. Five, vendor, from the nearest enclosing package. Six, the standard library table compiled into the binary. Disk always wins over the embedded table, so a project can pin a patched stdlib. Paths cannot escape: absolute paths, drive letters, angle brackets or dot-dot components are rejected with invalid module path on every backend. Packages are signed and immutable: a SHA-256 checksum plus an Ed25519 signature; publishing writes them, and republishing a version is refused. Verify re-hashes vendored trees, and editing one file fails the build gate. Semver accepts caret 1.2, greater-or-equal 1.2.3, and exact 1.2.3 — plain major, minor, patch only, no pre-releases. The lifecycle is add, tree, verify, publish, install.

[[SLIDE 7]]
Trust tiers T0 through T3. Four routes, and they do not carry the same authority. T0, the built-in standard library: embedded, immutable, no disk override. T1, project dot matrix files: the same trust as your own source. T2, vendored packages, checksum-verified, with verify re-checking them. T3, FFI with extern fn: trusted code, native builds only, and it runs outside every sandbox — use it only for your own trusted native libraries. Here is the honest advantage: dependency installation never executes package code. There are no Cargo-style build scripts. That is deliberate, and a real security win.

[[SLIDE 8]]
From a script to a standalone native executable. The build command compiles examples/hello.matrix to hello.exe, and running it prints hello. A desktop build adds release mode, an icon, and the Windows subsystem, using LLVM 23 with no external runtime dependencies. There are two documented ahead-of-time trades: the GUI bridge is not linked, and the execution budget is not enforced. The desktop flags: --icon embeds the icon resources; --subsystem windows selects a GUI with no console, on Windows only; --embed and --bytecode carry assets and compiled bytecode with no source or literals; --bundle-runtime appends the Spid3r executable so the app runs on machines with no installation; --product-name and --version write metadata; and --allow-gui permits GUI-native programs in a launcher build.

[[SLIDE 9]]
One self-contained file. Compile the app to bytecode, then build it with an icon, the Windows subsystem, the bytecode file, embedded UI assets and a bundled runtime. Inside the payload: the compiled bytecode, with no matrix source shipped; an index page and assets served from memory; and the runtime executable extracted to the local app data folder on first launch. What --bytecode buys is removal of source text, symbols and string literals. What it does not buy is secrecy — the VM is open source; it raises the cost from opening a text file to reverse-engineering bytecode. XOR obfuscation is not secrecy, so do not put secrets in client binaries. One system dependency remains: the WebView2 runtime, which is the default on Windows 11. Everything else is linked statically. And beware the launcher trap: the working directory is not the program folder, so point it at the app folder first, and launch helper processes hidden.

[[SLIDE 10]]
Six types and exactly forty keywords. Int is a signed 64-bit integer with hexadecimal, octal and binary literals, and an n suffix for big integers. Float is an IEEE 754 double with nan and inf. Falsy values are null, false, zero, zero point zero and the empty string — but an empty list is truthy. String is immutable UTF-8 with raw strings and negative indexing. Null uses double-question coalescing and dot-question chaining. Bytes is an eight-bit buffer capped at sixteen megabytes, with hex and base64 built in. Casting with as desugars to conversion builtins: x as int becomes int of x, and likewise for float, string and bool. The forty reserved keywords fall into eight groups: declaration, control flow, error handling, logic and literals, object-oriented programming, generators and enums, concurrency, and modules and casting. Every reserved keyword has a dedicated syntactic meaning.

[[SLIDE 11]]
Operators, null safety and strings. The precedence that matters: as binds tighter than multiplication; shifts cover zero through sixty-three; bitwise operators order and, xor, or; and double-question fires only when the left side is strictly null. If the user name is null, the display falls back to Guest User. If the account is null, the balance falls back to zero point zero through a safe chain. A nullable T narrows to T inside an if-not-null check, after early exits, after question-mark propagation, through dot-question, in a while-not-null loop, and on catch binders. For strings, use interpolation with user and score. Result with precision two, formatted from 88.6875, gives 88.69; precision zero applied to two point five gives two. The last character of Spid3r at index minus one is r. Methods include len, trim, split, replace, contains and format. Text inside braces with spaces stays literal, so use the no-space form; escape braces with a backslash or a raw string. Precision N runs from zero through fifteen and rounds half to even, unlike the round function, which rounds halves away from zero.

[[SLIDE 12]]
Flow, closures and higher-order function chains. If is an expression as well as a statement, so a status can be Passed or Failed based on marks. The three loop forms are a C-style counted loop, a for-in loop over a list, and a for loop over key-value pairs of a map. Fresh defaults: an empty list or map parameter allocates a new mutable collection on every call, never shared. A closure captures its environment: make_accumulator holds a running total and returns a function that adds to it. Functions are first-class values, closures remember state, and map, filter and reduce chain together. The higher-order functions are map, filter, reduce, for_each, all and any, plus sort_by, sorted_by and argsort.

[[SLIDE 13]]
Match, narrowing and guaranteed finally. An enum has variants such as Move with x and y, Rotate with degrees, and Stop. A match can guard an arm with a condition, bind the destructured coordinates, and provide a fallback arm. Here is the unit-variant trap: build a unit variant with Stop and parentheses. A bare Stop is the constructor function, valid only in a pattern; as a value it yields, function does not support indexing. Scrutinee-driven exhaustiveness requires a static enum match to cover every variant unless a wildcard or a binding is present. In error handling, try converts a string, catch prints the error and returns minus one, and finally prints cleanup. Finally is guaranteed, even when try issues a return, break, continue or unhandled throw. Option has some and none; Result has ok and err; all filesystem primitives return a result. Internally, on a throw the VM restores the stack exactly, so every catch sees a clean state. The checker recovers up to twenty-five syntax errors per pass.

[[SLIDE 14]]
Classes, inheritance and interfaces. The Animal class has a public name, a private energy field, a constructor that sets both, and a speak method returning a string. The Dog class extends Animal, declares a breed, calls super with the name to delegate to the parent constructor, and overrides speak by appending Woof to the superclass result. The core rules: self is an explicit first parameter, default visibility is private, inheritance is single through extends, call the parent with super of args and super dot method, and use abstract classes and public static functions. Interfaces such as Drawable can carry default method bodies, and a Circle implementing Drawable dispatches through a heterogeneous list. There is a gradual unchecked case: a private field access is rejected when the receiver's class is statically known, but with an untyped variable it is a gradual unchecked case.

[[SLIDE 15]]
Generics and twenty-plus data structures. Generic bounds include Numeric, Comparable, Printable and Drawable, with intersections such as Numeric plus Comparable, and explicit forms like identity of int. Unannotated generics fall back to type erasure in the tree and VM, and both run generics polymorphically with zero behavioral divergence from ahead-of-time code. Collections include List with constant-time append and index, Map with constant time via FxHash, Set, Bag with no set algebra by design, immutable Tuple, Stack, Queue and Deque, Heap, Trie, Graph with Dijkstra and BFS, ring buffer, linked list, hash table, binary search tree, binary tree, priority queue, dynamic vector, and a sixteen-megabyte bytes buffer. Stable comparator sorts snapshot the list and hold no lock while a comparator runs, so a throwing or mutating comparator never deadlocks or panics the host.

[[SLIDE 16]]
NumPy, replaced, with no install. Contiguous 64-bit float buffers, capped at sixteen million seven hundred seventy-seven thousand two hundred and sixteen elements, with zero external dependencies. Operations include matrix multiply, vector dot, Hadamard product, transpose, determinant by Gaussian elimination, inverse by LU decomposition, solve by partial pivoting, and mean, sum and trace. The layout is row-major: a flat index addresses row times columns plus column and returns a float; the two-index form is not used, so use get and set for two-dimensional access. Here is the result: the dot product of one, two, three with four, five, six is 32.0. The determinant of the two-by-two matrix four, seven, two, six is 10.0, and solving against eighteen, ten gives three point eight and zero point four. Save and load use the standard NumPy version one point zero format with little-endian doubles, and the trace is also 10.0.

[[SLIDE 17]]
Real concurrency, with no interpreter lock. Spawn returns a task handle. An M:N scheduler uses one shared ready queue. A channel is an unbounded first-in-first-out queue, and recv blocks until a value arrives. Here a worker task sums one through a hundred and the main program joins it to get the result. The worker limit defaults to two hundred and fifty-six, with OS threads grown on demand. Also available: async and await, task join, mutex, an atomic integer, and strong and weak references. There is no global interpreter lock, so two CPU-bound tasks really do run at the same time. For deadlock safety, built-in deadlock detection aborts when no task can make progress, and exit waits briefly for still-running tasks.

[[SLIDE 18]]
Stdlib and the twenty-six modules. Console and runtime provide println, spid3rinfo and config_get. Filesystem has streaming handles capped at one thousand and twenty-four. Process, network and events cover http_fetch, Unix domain sockets and poll. Math and random provide random_bytes from the operating system CSPRNG. Crypto covers sha256, hmac, ed25519 and argon2. Formats cover JSON, CSV, gzip and regex with an NFA. All twenty-six modules compile into the binary: web, http, fastcgi, stats, mathx, toml, yaml, xml, tz with tzdata 2026e and five hundred ninety-eight zones, unicode with UCD 15.1, smtp, ftp, session, middleware, multipart, event, gen, bigint, complex, decimal, rational, semver, uuid, testkit, assert and mock. Exported functions keep a module prefix: uuid dot uuid_v4, not uuid4; toml dot toml_parse, not parse; event dot start, not new. Top-level symbols must be public to export.

[[SLIDE 19]]
The cryptography trust statement. Not independently audited. Standard hashing and signing primitives — sha256 and 512, hmac, pbkdf2, ed25519, bcrypt and argon2 — are pure Rust with zero dependencies, verified by internal RFC vectors and negative and malleability tests, while TLS transport uses vetted OS native-tls and primitives are not formally proven side-channel hardened. External review is pending. For high-stakes production, terminate TLS or run secret-key operations behind an audited reverse proxy or HSM. Ed25519 uses a constant-time Montgomery ladder with canonical scalar checks and rejects small-order and off-curve keys; verification is strict but not constant-time. Only random_bytes is cryptographic; random integer and float use a clock-seeded generator and are never suitable for tokens. JWT verify is constant-time with a sixty-second skew, but checks HS256 only and does not pin the algorithm to a policy, so do not feed it tokens from an issuer you do not control. Constant-time by construction: bcrypt verify and secure compare.

[[SLIDE 20]]
One INI file, one control panel. Discovery is first hit wins: an optional environment pin, then spid3r.ini beside the executable, then the platform config directory, then a local spid3r.ini. Precedence runs from the environment, through the INI, to compiled defaults. Invalid values are ignored with a note, and reload happens through config reload. The schema has forty-five keys across twelve sections. Here is the honest point: basedir is not a jail. Process tools reach any path the OS user can, so pair it with sandboxing or disabled native calls. And everything is local: the spid3r control command covers status, safety, ini, config and logs, and the desktop control panel mirrors it with overview, language, safety, configuration and logs tabs. Config, control and logs all stay on your machine.
