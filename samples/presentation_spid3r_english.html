Security Boundaries

Clear trust levels (T0, T1, T2, T5)

Four ways code enters your app — each with a clear trust label.

T0Built-in toolkit — compiled inside Spid3r, locked and unchangeable
T1Your project files (.matrix / .mt) — code you wrote and control
T2Downloaded packages (vendor/) — fingerprint-checked via spid3r verify
T5Native C plugins (extern fn) — full system access, native builds only
Why T5 needs trust: Native C plugins run outside any sandbox — only link libraries you trust completely.
Zero install-time surprises: Installing a package never runs hidden setup scripts — it only copies verified files.

Easy Distribution

Ship everything in one single file

What's packed inside

Compiled bytecode (no readable source text), UI files served straight from memory, and a SHA-256 verified runtime unpacked on first launch.

What --bytecode does: Removes plain source code and text literals. Honest limit: Skilled reverse-engineers can still inspect bytecode, because the VM is open source.
Never hide passwords in client apps: Obfuscation is not encryption. Only OS WebView2 (already on Windows 11) is needed externally.
Shortcut tip: Desktop shortcuts may start in the wrong folder — check your app's own folder first with exe_path().

Smart Checks & Recovery

Match every case & clean up safely

enumMove(x, y)Rotate(degrees)Stop
return match (cmd) { Move(x, y) if x == 0 and y == 0 => "Hold", Move(x, y) => "Move to ({x}, {y})", Rotate(deg) => "Rotate {deg} deg", Stop => "Emergency Stop!", _ => "Unknown" };
Quick rule: Create empty variants with parentheses like Stop() — bare Stop is only for matching patterns.
Nothing forgotten: match makes sure you handle every option (or add a fallback _) before the code even runs.
try { let val = int(s); } catch (err) { println("Caught: " + string(err)); return -1; } finally { println("Cleanup: completed"); }
finally always runs — even if try or catch hits return, break, or another error.

Explicit results: some(v) / none · ok(v) / err(e) — file operations return result instead of crashing.

Clean recovery: When an error is thrown, the program resets safely so your recovery code starts fresh.
Organizing Code

Classes, inheritance & shared rules

class Animal { public let name; private let energy; public fn new(name: string) { self.name = name; self.energy = 100; } public fn speak(self) -> string { return self.name + " makes a sound"; } }
class Dog extends Animal { public let breed; public fn new(name: string, breed: string) { super(name); // reuse Animal setup self.breed = breed; } public fn speak(self) -> string { return super.speak() + " (" + self.breed + ") -> Woof!"; } }
Simple OOP rules: Details are private by default · self is written clearly · reuse parent blueprints with extends & super · supports abstract & static.
Interfaces: interface Drawable defines shared abilities (even with default code), so different shapes work together in one list.
Type note: Private field access is checked up front when you write the class type (let c: Dog = ...); untyped variables check dynamically.

Security Honesty

What our built-in encryption promises — and doesn't

Not independently audited yet: Built-in password & signing tools (sha256/512, hmac, pbkdf2, ed25519, bcrypt, argon2) pass standard security tests with zero outside libraries, while HTTPS uses your OS native-tls — an independent outside review is still pending.
For critical production apps: Put HTTPS and secret keys behind a trusted security gateway (like nginx) or hardware key vault (HSM).

Ed25519 Signatures

Strictly blocks forged keys, though verification is not timing-attack hardened yet.

Random Numbers

Always use random_bytes(n) for passwords/tokens — random_int/float are fast math generators, not secret-safe.

jwt_verify: Timing-safe check with 60s clock leeway, but supports HS256 tokens only — only accept tokens from servers you control.
Timing-safe comparisons: bcrypt_verify and secure_compare are built constant-time by design.
